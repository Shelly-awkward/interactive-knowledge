# T4 結局整理表與重玩

你負責結局畫面：用兩個韌性問題給評語、另一路線對照、案例整理表、學習紀錄、重玩。

## 目標

實作 `CG.ui.renderEnding(el, ctx, {onReplay})`，覆蓋 `STUBS` 的陽春版。`ctx = { game, actual, other, rows, learning }`（見 `SPEC.md` 第 3、6 節）。畫面由上到下：

1. **揭曉路線**：用 `CG.ui.renderAdvisor`（若存在）或一般段落，顯示 `advisor.endingReveal`，`{route}` 換成實際路線名稱（`GAME_DATA.routes[actual.routeId].name`）。
2. **兩個韌性問題**（`text.twoQuestions`）：
   - 第 1 題答「會／不會」，附上三回合中最低的產能與是哪個回合。
   - 第 2 題答「會／不會」，附上長期回合的年現金流（`CG.core.fmtYi`）。
   - 評語區塊有 `data-verdict="{actual.verdict}"`，顯示 `ending.verdicts[verdict].name` 與 `.text`。
   - 如果 `rows` 只有一列且風險是「無可合理預期的氣候風險」，評語文字改用 `ending.noRiskConclusion`。
3. **另一路線對照**：`ending.crossRoute`（`{route}`、`{verdict}` 換掉）。兩條都是 `resilient` 時再加 `ending.bothOk`。下面一張小表：兩條路線 × 三回合的產能與年現金流，產能低於 80 或現金流小於 0 的格子標紅並加文字（不能只靠顏色）。
4. **整理表**：欄位用 `ending.tableHeaders`，每列來自 `rows`（`risk, kind, data, impact, measures, conclusion`），每列外層有 `data-row`。`flags` 有 `demo`／`assumed` 時，在「影響」欄加 `CG.ui.srcTag`。「類型」欄依實體／轉型／機會上色並有文字。手機 375px 時改成一列一張卡（每格前面有欄名），不能橫向捲動。
5. **學習紀錄**：`learning` 的六步驟，各顯示「答對 n／m」。
6. **底部說明**：`text.disclaimer`、`text.fictional`、示範數字來源 `meta.source`，最後一句大字顯示 `ending.finalQuestion`。
7. **三個重玩按鈕**：`<button data-replay="otherRoute">同公司，換另一條路線</button>`、`data-replay="changeCompany"`（換一家公司）、`data-replay="restart"`（從頭開始）。點了呼叫 `onReplay(mode)`。

加分項（不強制）：「列印這張表」按鈕（`window.print()`）與列印樣式。

## 輸入

- `dev/韌性航線2100/SPEC.md`（第 2、3、6 節）
- 遊戲檔的 `DATA`（`ending`、`routes`、`text`、`advisor.endingReveal`、`meta`）、`STYLE-CORE`、`CORE`、`STUBS`
- `CG.core.summaryRows`、`CG.core.learningRecord` 的輸出格式（讀 `CORE` 區塊）

## 輸出

只改遊戲檔的 `ENDING` 與 `STYLE-ENDING` 區塊。

## 驗收標準

```
node dev/韌性航線2100/tests/accept.mjs --only=common,T4
```
